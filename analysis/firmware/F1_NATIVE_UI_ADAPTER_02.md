# F1 native UI adapter 02: finite selector, owner and repaint source stage

This is static analysis, owned host validation and AArch64 ET_REL compilation. Temporary camera execution, persistent installation, native menu/render acceptance and RAW/JPEG isolation acceptance are **false**. Original firmware, SDK and camera were never executed by this task. F4 is paused. Frozen `f1_native_overlay_01` is unchanged.

All addresses below bind solely to User ELF SHA256 `9b611efe64067685b770ba3984ae951684c5a401f73f77a03b316be374032cdb`, 11,874,544 bytes. Captured code/rodata file offsets are `VA - 0x400000`; exact byte windows, offsets and hashes are in `f1_native_ui_02/static/exact_bytes.json`. They do not bind a Factory ELF or identify a running User by version text.

## Shortest positive route and precise remaining entry gap

Original LV owns a **pre-existing** selector Dialog at `LV+0x588`. Its constructor call `0x517958..0x517970` uses x0=LV+588, x1=manager, x2=null initial menu, w3=0x2ee, w4=1. Complete selector constructor `0x4fad38..0x4fb1cc` shows w3 is **750-pixel list width**, not a title resource ID. The primary address point is `0xb931b0`, embedded Dialog node at +88 is `0xb933e0`, Navigator at +128 has VT `0xb90020`, native observer is +108.

Original LV control handler `0x51f9fc..0x520298` already calls `SetMenu` then `DialogShow`: `0x51fe08/14` uses LV+1048; `0x520218/24` uses manager configuration +110. The original touch/key implementations, controls, resources, Surface and page return can be reused. This source does **not** replace the existing tag 1/8 action or append to LV+1048/global menus. Its `open_on_ui()` is a real finite selector entry implementation, but connecting a retained user-facing native action to it is still a **static routing gap**, not merely a missing evidence boolean. A subsequent increment must close the native original-menu insertion/removal/listener contract or an explicit new stock action route before enabling it. No desktop UI or new GUI framework was created.

When a verified original UI control event invokes this entry, this source builds one private native `UiSubMenuItem` and five `UiEventMenuItem` objects, then sets the existing selector's root through the original method. OFF/native, XPan65:24, 16:9, 3:2 and 1:1 only target the frozen overlay's own selection bridge. There is no native crop, capture, RAW/JPEG, file/config, recorder or security setter.

The finite source accepts only an **unused** original selector: initial root+300=null, current root+18=null, stack[0]=null, depth0, selected=null, and ordinary stack LV-current. A non-null/occupied selector is rejected without native calls; it does not overwrite a stock navigation session. It copies the original popup+e0 header's observed U32 +88 title into the own submenu, so native `4fb390 -> 4fa688 -> 4faa5c` writes the same resource value. Return verifies that value is unchanged; it invents no title/resource ID.

On selection, a queued original OsEvent reaches the own native observer on the real UI queue. The overlay selection bridge first demands an actual full-source `ViewMapping` and geometry epoch. On success the selector closes via original Close, requires LV-current, resets the menu via original SetMenu(null), verifies root/stack/depth/selection/title and the exact Navigator/menu-change subscription triple **Absent**, then invalidates LV. Native Back may already have closed the popup; cancel permits that specific return shape and still resets/verifies the menu. It retains all native events, submenu/items/labels/list nodes/observer/code until stock process exit. Event destructor does not remove the global registration nodes; no hot unload, manual list write, free or delete is supplied.

## Corrected repaint names, force and receipt boundary

Older frozen UI material labels `0x4e14bc` and `0x4e4820` as a close request. That name is corrected here without rewriting those freezes:

* Configurator+a98 is constructed as OsEvent **"UiIQ4Redraw"** at `0x4ed6a0..0x4ed6b4` (string VA b91798); constructor call `0x4edbf8..0x4edc40` passes it in x4 and manager stores it at +100.
* Ordinary Control invalidate `0x4ac06c` sets dirty+6d and calls VT+128. For LV this is `0x4e14bc`; it schedules `0x4e4820`, not Close. `4e1a14` returns manager+100. `4e159c` tests whether this is current.
* Manager event handler `0x4e3030..0x4e30c4` matches +100, calls VT+b0=`0x4e32d4` with w1=1, then optionally presents Surface through manager+108 VT+10.
* Complete renderer `0x4e32d4..0x4e36b8` obtains current Dialog and Surface and calls Dialog VT+98 with w4=1. Complete Control draw `0x4abd24..0x4ac06c` uses dirty **or** w4 force to call original parent paint, then its children. True Close remains `4e1320 -> 4e2bdc`.

This is a positive original **force-dirty redraw request**, not full-image coverage proof. Original LV paint `0x51da0c..0x51df64` still skips image writes on running=false, absent source/lock failure, countdown!=0 and clip/geometry branches. Its positive incoming draw-rectangle return and Surface dirty union cannot certify fresh image pixels. The selector therefore tracks request generation and rejects stale/duplicate receipts; partial coverage or no completed image blit remains Pending. OFF can be marked restored only after an actual fresh stock-image receipt covering its image viewport. Overlay01 separately retains its old/new viewport union until coverage clears it; this source does not weaken that rule.

## Actual owner, geometry and enable conditions

`Inspector::boundary` reuses the frozen original UI queue boundary, without any ready booleans or external owner parameter: architectural TP+10 -> queue VTb91f48; queue+1c8 manager VTb8f358 -> manager+8=queue; queue+9b8 CoreUiData=manager+790; queue+8c0 LV VTb9a9d8 -> LV+b0 manager, and its existing popup/Navigator VTs. Double reads must agree. Actual after-original-unlock PC6be8ac, mutex queue+f8, bounded actual FP chain must contain saved71396c -> pop saved70ff9c -> dispatch saved4ef984, matching [pop+28]/[dispatch+18] queues and popped observer. Maximum24 frames, 64KiB steps, 1MiB span, bounded reads. The previous Bootstrap static evidence remains a frozen dependency; no source/frame event is registered here.

Readonly Current inspection rejects manager+c8 override, +d8 auxiliary, +e0 active and nonempty priority stack. It currently accepts **only** LV alone or LV then its own popup on the normal stack. Native Current reads the **tail**: `4e4e2c -> 70bcc0 -> 460394(+10)`; original Push appends before sentinel via 70bc18/70bb78. Reversed chains are rejected. A real Home/other stock page below LV would currently be rejected and must be separately captured before widening this finite shape.

The candidate geometry reader returns LV local Control Rectangle24 at +28, pan at +110, **float32** scale at +190, quarterturn+1b0, countdown+1b8 and visible/running bytes. It never reads Surface+38/source pixel pointers, buffer content or RAW dimensions. Original `4ab9d8` recursively converts parent bounds through VT+130; consequently local bounds are not screen image viewport. Full-source dimensions/ROI, focus zoom and affine display mapping must be observed and independently validated before the `GeometryPort` can produce them. Unknown geometry remains rejected/hidden.

`resolve_static_candidates` reads exactly 12 first-16-byte entry signatures and returns typed static candidate pointers. That is a finite integrity check **only**; it does not establish the entire mapped User, runtime ABI, thread, triple ownership or object lifetime. It neither calls candidates nor fills the actual thread/triple/geometry ports. `Selector::configure` is unconditionally false in production even if all pointers or apparent bytes match. No enabled artifact, vptr writer, constructor/interposer, installer or device payload is included.

The next actual **readonly** observations needed are: running User whole SHA/size and nonwritable segment identity; real architectural UI boundary/normal stack/embedded popup state/title/lifetimes; exact native triple inspection under original locks; ResourceProvider -1 text fallback; original LV pan/rotation/zoom/source-to-display geometry; and fresh image-write/clip/viewport coverage/serial. Only after those facts and the retained user action route close can a separately reviewed RAM trial execute. Its acceptance must include all five modes, original touch/key/menu return, OFF/disable full restoration, observer detach/later boundary and independent RAW/JPEG unchanged evidence. No such observation or acceptance occurred in this stage.
