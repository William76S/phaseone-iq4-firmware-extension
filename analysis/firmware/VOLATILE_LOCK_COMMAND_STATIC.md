# Original OsEvent Locked route — finite static contract

The original `OsEvent` directory registers the native `Locked` bool event. Its set branch performs whole-name matching, decodes a canonical decimal bool and emits the native notification. This is a concrete **static candidate for temporary state restoration**, not a device-tested unlock or persistent PIN repair. No camera, SDK, transport, actual code/token, calibration or key was accessed; no event or record was changed.

All addresses bind only the local User candidate `analysis/firmware/extracted/P1Linux_6.03.21.bin`, 11,874,544 B, SHA256 `9b611efe64067685b770ba3984ae951684c5a401f73f77a03b316be374032cdb`, BuildID `1f451370d713ae1f341e9d5de5615717f9fb36ed`. Display version 6.03.18 alone does not prove the running User matches this ELF. Do not apply these addresses to the separately read Factory ELF. `volatile_lock_command_static/exact_bytes.json` records section-derived offsets and original bytes, including complete handlers where needed. `.text`/`.rodata` offsets equal VA minus 0x400000; initialized data and dynamic relocations must use the recorded section mapping.

## Command registration and direct event ownership

1. Shell is created at `0x40bc18..0x40bc58` and retained through global `0x3d29d68`. C main registers a newly allocated 56-byte OsCommands instance into `Shell+0x30` via the same directory's VT+0xb8 at `0x40bdf4..0x40be3c`. Constructor `0x6ba4e4..0x6ba730` installs VT `0xc14108`; `0x6ba570..0x6ba594` registers command name `0xc132d0="OsEvent"`, command ID 2. VT+0x48 points to `0x6bd814`. ID2 dispatch `0x6bd844..0x6bd988` calls `0x6bb978` with the command context.
2. The same Shell+0x30 owner is passed to Main at `0x40bd78..0x40bdbc`, retained in Main's frame, and passed to the DevelopmentShell constructor at `0x424700..0x424714`. The latter reparses the quoted body and invokes directory VT+0xa8 at `0x8728c8..0x872a38`. This is a positive shared-owner path; development advertisement is not Start/authentication/execution proof.
3. PinGroup constructor `0x63da2c` names bool object `PinGroup+8` with string `0xbe1ba0="Locked"`, default true. Its `0x415354` bool constructor calls `0x70f12c` on interior event `PinGroup+0x10`. Event constructor `0x70f12c..0x70f208` calls `0x711aa0`; the latter appends a node whose +0x18 is that interior event to **OsEvent registry `0x3eac990`**. This is a different directory from DataObjects at `0x3eac9c8`.
4. Event VT `0x9f1988` slots are +0x18=`0x418760` (formatter thunk, subtract8→`0x418298`), +0x20=`0x418bd4` (decoder thunk, subtract8→`0x418768`), +0x28=`0x418290` (type-name thunk→`0x418270`). Relocation `R_AARCH64_COPY _ZTIb` at `0xf42d40` identifies bool RTTI; its loaded name is returned via `0x40bfb4`. File-backed zeros there are not the runtime RTTI contents.

## Finite read and set semantics

The following are recovered text contracts for a future sole executor. They are not outgoing USB packets; no SDK/transport operation is included in the host helper. They must not run before the conditions below.

| Purpose | Quoted command body | Exact behavior and limit |
|---|---|---|
| Narrow read | `"OsEvent list Locked -f"` | `0x6bc5cc..0x6bc7d4` iterates OsEvent registry and formats only matches. **Plain name filter is a case-insensitive prefix**, through `0x744e8c/0x744ff4`; it is not exact selection. Full-name output (`-f`) avoids the default 32-character name truncation. Require one row only, name exactly `Locked`, type `b`, canonical value `true` or `false`, complete response and no unexpected rows/output. |
| Conditional temporary clear | `"OsEvent set Locked 0 -f"` | `0x6bbbf0..0x6bbf0c`: `set` token is whole-compared; event name at token2 is compared via `0x7408d4`, w3=1. Canonical token3 `0` enters bool decoder; absent `-ns`, `0x6bbe70` calls `0x70f2f8` on the matched event. Every duplicate whole name is processed; it does not reject duplicates. Read uniqueness is required first. |
| Restore original true | `"OsEvent set Locked 1 -f"` | Same native path with canonical decimal `1`. Requires original typed state=true, then independent readback and original permissions/state restoration. It is not PIN entry or a code edit. |

`0x7408d4..0x740a70` takes token/name bounded lengths below50; whole comparison adds1 to the smaller length and compares through the terminating NUL, with case handling selected by command-context +0x298. These fixed six-character names do not reach its 50-byte ambiguity. The set branch matches every whole-name event rather than stopping at one or verifying uniqueness.

Bool decoder `0x418768..0x418bd4` obtains current field at owning bool object+0xc0. Its bool branch `0x418a08..0x418a5c` calls `sscanf(value,"%d",&local)`, then stores `(local != 0)` to that field. **The conversion return is not checked. Never use `true`, `false`, an empty string, a missing value, hex, or a general expression as the setter value.** Only exact ASCII `0`/`1` satisfy the finite contract. Unlike ordinary setter `0x4149b0`, this generic decoder does not perform the captured critical-section/change test; notification is separate in OsEvent set. It must run with ordinary user operations quiescent and one executor.

The formatter's bool branch `0x418628..0x418684` emits `true`/`false` with `%s`; setter syntax and reader syntax intentionally differ. `0x6bdfb0..0x6be390` writes a two-line heading followed by `"  %-32s%1s   %d     %c   %-28s %-16s %u\n"`. `-f` expands the copied name limit to63; it does not construct a group-qualified name. Notify display is blank/`0`/`1`/`H`; log is the event bool and final unsigned count is waiting threads. The host validator rejects additional/prefix-collision rows and unknown output rather than trimming them.

The body is one quoted token in the first parser: `IqpDevelRaw` + quoted body. DevelopmentShell reparses token1 into `OsEvent`, `list`/`set`, `Locked`, and the finite remaining tokens. `=` is unnecessary. This path **does not use Sys's destructive rejoin**; do not apply Sys's reconstruction to a DataObjects or OsEvent command. No inner quotes, backslash, newline or arbitrary name are needed. The existing native-development contract still owns Common headers, authentication, payload span, correlation, sequence and lifetime. A text completion is not a numeric success status, and a formatter row is not proof all asynchronous observer work completed.

## Native notification and persistence boundary

`0x70f2f8..0x70f4e4` dispatches the original event's subscribed listener list via listener VT+0x10 under the captured list lock. The following positive observers are established; this is not an exhaustive alias/callback exclusion:

- SecurityHandler constructor `0x6aab5c..0x6aac4c` subscribes exactly to PinGroup+0x10. Its callback `0x6aac4c..0x6aac70` calls permission recompute `0x6aac70..0x6ab23c`. Recompute reads Locked and SecurityLevel, sets `Unlocked=!Locked`, changes PinDTO and the second DTO group's lock flags, updates all four `Unlock*` bools, and invokes four guard VT+0x48 setters. With Locked=false, all four permissions are true. DTO wrappers `0x5efaa4→0x5f1acc` and `0x5afd18→0x5b4f08` change the wrapped state block U32 and notify its original event; they are not the SecurityLevel value setter.
- Positive owner binding: Main `0x41b10c..0x41b128` creates PinDTO, `0x41b1b4..0x41b1d4` creates the second DTO group; `0x41c090..0x41c0dc` passes both to SecurityHandler constructor, which stores +0x20/+0x28. This avoids labeling arbitrary wrappers as security state from proximity alone.
- PinUI callback `0x576a28..0x576a80` matches Locked event identity, reads UnlockUI and shows the original dialog only when that permission is false. It returns through `0x576cfc`. Keyboard-completion processing at `0x576b48..0x576ca4` is a different event-identity branch; the matched Locked branch does not fall into SetPinCode.
- PinHandler constructor's captured subscriptions are PinCode+0xe8 and SetPinCode+0x1c8, **not Locked**. Its captured record-1 writer is reached by the SetPinCode branch only when unlocked. System storage captured registrations persist PinCodeFails and SecurityLevel, not Locked. Those bounded facts do not prove every indirect observer is storage-free.

The four guard virtual implementations and the DTO state notifications' secondary observers are not exhaustively closed. Do not claim global no-write from absence of a direct BL. A reversible trial needs full raw EEPROM backups and **complete raw before/after equality**, stable program/owner, typed Locked and native permission readback, an explicit original-event true rollback and final false only after successful rollback. A temporary clear normally disappears when the application reconstructs/loads Locked on restart; no promise of surviving reboot is made. No PIN record is cleared or decoded by this route. This narrow increment did not find or generate a verified native undefined-PIN/clear recovery entry.

## NoLock is an independent candidate

Permission function `0x6aad44..0x6aae38` grants all four permissions when Level=0 and Locked=true, but it already set `Unlocked=false` and DTO lockflags=true. This is **disabled restrictions**, not Locked=false. Only SecurityHandler's Locked subscription is captured; a Level setter's immediate recompute bridge is not proven. The existing recovery UI report shows the native Level menu itself has a Locked guard. After a verified temporary clear, the native NoLock UI or typed SecurityLevel DTO would be a separate persistent setting action: preserve the original full EEPROM and typed Level, prove its setter/notification and restore round trip, then test native permissions. Do not change PinCode, key records, global EEPROM or code-entry counters to obtain that state.

## Concrete execution conditions and host result

1. Native FF.0 Start/protocol/authentication and single-command response ownership must pass. Advertisement and host-agent presence alone do not pass this gate.
2. First use the finite original Sys reads to identify actual process executable path/hash/metadata and the dynamic EEPROM leaf/tool support. Match current User SHA exactly before relying on this static map. Preserve two complete equal raw EEPROM originals with private storage/ACL evidence; do not decode actual PIN/key values.
3. Complete the narrow read through the original SDK development sender, assemble exact response spans/final fragment, and require exactly one typed canonical Locked=true row. The readonly filter is prefix-based; any extra row is a failure. Retain native permission baseline and quiescent status.
4. Only then consider the original bool set0 and independently read back false plus native gate availability. Compare complete EEPROM originals again. Perform set1 rollback, read true and original gates, compare raw EEPROM again. Stop on identity change, missing final fragment, duplicate name, unexpected mutation, lost event owner, error or failure to restore. Thread/guard secondary effects remain an explicit live verification item.
5. A successful temporary false→true round trip permits a final temporary false under the user's authorized recovery scope. It does not establish persistent repair, recording installation, an authentic 60fps source or F4 completion.
