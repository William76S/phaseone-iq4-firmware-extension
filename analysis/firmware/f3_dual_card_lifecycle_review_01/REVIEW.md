# Frozen Executor03 / Coordinator08 selected-mask and ownership contract

This is an offline review of the actual frozen Producer03, Executor03 and Coordinator08 source. It does not establish camera acceptance or a native frame rate. The frozen header and source manifests are unchanged.

Producer03 sets `selected_mask` only after the original fanout enable getter returned true and the actual native storage-context weight is SD=4 or XQD=2, with that card's non-RAW project policy. This happens in the exact original fanout path before its immediate original Notify. The mask is therefore an actual selected-for-notification card set, not callback arrival, successful Notify delivery, completed save, successful JPEG, or inferred physical-card presence. It can grow while the original fanout runs. The separate hook after original SetRefs returns seals the selected set. `finished_mask` records normally ended project per-card cleanup/refusal separately. The producer may release its shared activity only after the set is sealed, all selected bits have normally ended, no card serialization owner exists, and no Hold was latched. Mask equality alone is never a JPEG-success claim.

The stable header `tools/firmware/f3_native_executor_03/saved_capture_contract.h` already states actual native-selected/notified destinations, not completed callbacks or inferred card presence. Its SHA256 is `f8856fb4c05170020f443420653271f27524204b970fee9a9872371d7a079a1e`; both Producer03 and Executor03 SOURCE rows bind those exact bytes. The words selected/notified do not mean the subsequent native Notify was observed to return normally. Executor03 accepts own-bit-preserving mask growth while requiring unchanged receipt/group/card/capture sequence/activity identity.

Both native stores read original RAW memory payload and metadata and write their own card File/FS. They do not read a peer card's IIQ path. Producer03 creates its own file exclusively, keeps the actual checked writer-close result, whole file hash/EOF and held reader FD, and supplies a static-slot proof. Thus each JPEG-only branch may remove only that independently created inode after its actual render/source object cleanup and fresh whole-file/inode checks, while its own source/card owners remain held. No claim is made that the peer native write finished; no speculative peer-path deletion fence was inserted.

Producer03 serializes the actual Card06 sole request and complete per-card File/receipt lifecycle. Executor03 independently reserves the sole IFM mailbox before Coordinator08 places its sole Job, so another card cannot overwrite an active Job. Coordinator08 copies the producer's immutable early dependency snapshot and rechecks it, rather than dereferencing a later RawManager current node. Before-enqueue BUSY/REJECTED acknowledges normally and retains original RAW without preparing the unrelated Job. A known preparation refusal cancels only the empty mailbox. Unknown, Notify failure, queued timeout, changed identity, codec cleanup uncertainty, failed native cleanup or cancellation uncertainty retains the receipt, group, job, card/source/reader/arena and worker owners. The executor never releases a borrowed producer group lease.

Actual host evidence comprises Executor03's 18 focused +17 inherited groups in normal, ASan/UBSan and TSan; Coordinator08's 18 routing +5 actual saved-prepare +11 inherited no-enqueue +16 actual cleanup/sink groups in normal and ASan/UBSan. All 205 group executions returned zero with empty stderr. Native callbacks and producer proofs remain explicit host fixtures; two AArch64 object compilations per module were byte-identical. Parent performs full linked-ELF guards, sealed User/FWP reproduction and any separately controlled camera test.
