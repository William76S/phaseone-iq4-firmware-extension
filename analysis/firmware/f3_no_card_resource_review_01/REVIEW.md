# No-card complete RAW RAM source and native render resources

This finite review reads the fixed original User and Boot locally. It does not call native code, access the camera/SDK/Windows, change frozen implementations, or establish a new no-card JPEG feature. The exact Host/Capture One consumer route is independently owned by firmware_map in `f3_host_no_card_transfer_static_01`; this report does not replace that transport proof.

The original renderer does have an encoded RAW RAM input branch. `7b7810` acquires the node's payload resource via `8c25c0`; `495094` returns resource+0x40. `7b7834` acquires its separate metadata resource via `8c2750`; `4950ac` also returns resource+0x40. The names TestBuffer/FrameBuffer neither establish nor negate full RAW. `7b78f8` passes the actual payload and metadata to native BuildTags. `7b7978` copies the payload's uint32 offset vector at +0x10 into the native input's own vector; `7b7990` stores the payload data pointer from +0, and `7b79b0` stores the U32 encoded length from +0x2d888. `7b79bc/7b79c4` map metadata+0xc4 through `7b6314`; actual source enum5 maps to native codec8. No target value of that metadata field was observed in this review. Current render/decode02 admits codec8 only.

BuildTags is **not** a small generator method. Its actual arguments are `(large ICE context, owned mutable tag map, payload, metadata)`. It writes WB member data to context+0x655479a0, then installs a borrowed 12-byte blob pointing there; it writes several other fields near that huge context range. It also accesses context+0x1b8 for calibration/profile lookup and installs that native manager's blob pointer at tag0x110. `7bb214` releases its temporary lookup holder afterward; that borrowed pointer's continuing cache lifetime cannot be replaced by a caller assertion. Passing a 0x1f0 owned generator in place of this context is a concrete out-of-bounds ABI mistake. The independent Saved-IIQ builder avoided this method by building a small original map with checked scalar/blob assignments; a RAM-source builder must likewise create its own map, stable WB storage and owned/held black/calibration/profile bytes, rather than call this method on the small renderer.

Geometry comes from metadata+0x58/+0x5c (total W/H), +0x60/+0x64 (left/top), +0x68/+0x6c (valid W/H). BuildTags copies these to native tags0x108/109/10a/10b/10c/10d. Its black/row-calibration blob branches depend on metadata+0x45c, not merely width/height. The RAM branch also uses the payload's native profile string at +0x2d890 through `960b48`. This is not a proof that the Saved-IIQ first-byte-zero/profile-slot-zero branch can be forced on every capture. Preserve actual original color/profile selection or reject an unproved branch; do not invent sRGB/ICC/LUT metadata.

The already-frozen source01 is tied to an actual independent native reader's held read-only **regular POSIX fd**, exact fstat/pread counts, whole IIQ section comparison, and checked reader close. A native MemoryFS File's fd-shaped field or an arbitrary synthetic FileOps identifier cannot stand in for that contract. Render02 also explicitly requires this concrete SourceBundle. A new RAM adapter requires a new checked source interface; casting another class or setting an existing completion flag true is not integration.

The smallest legitimate future interface consists of an actual capture identity and resource lease; total/crop geometry and codec; owned copied row offsets with count exactly total height; a held complete encoded payload extent plus the decoder's physical padding; an independently constructed original RawInput/map; stable calibration/profile/WB storage; and a recheck callback tied to the same actual node/resource identities. The original native input factory `7bbac0`, map factory `7bba0c`, map index/value setters `7bcc64/7bb8e0/7bb910/7bb940`, and vector push `7bc7e4` are already in render02's exact-bound source API. Row offsets must be bounded/ordered and match the actual complete payload; data/compression producer completion and physical allocation extent must be derived from native production receipts or checked whole-source construction, not a caller boolean. The existing combined decoder and core receipts remain necessary after this input is ready. The renderer, encoder, native map/vector and all jobs must finish and clean normally before releasing these actual resource leases; Unknown retains them. A source lease is separate from a transport/group activity lease.

External memory is accepted by original generator constructor `962058(self, base, uint64 capacity)`. It uses the first 80 MiB for native prefix regions, then stores remaining capacity/base at generator+0x198/+0x1a0. There is no file-backed-only semantic in that constructor: an actually held aligned RAM reservation could supply the same contract. Native decoded data and core image allocations still consume this space; individual CIB byte sizes use signed 32-bit quantities, while their arena sum is 64-bit. Native capacity early-return is not completion, and the core receipt deliberately rejects it.

| Valid RGB32 | 605,374,464 |
| Valid planar | 151,343,616 |

| Sample encoded RAW + decoder padding + row offsets | 160,007,376 |

These are necessary minima for the current full-R0 route, not a sufficient working-set limit. Original other owners, whole-IIQ transport buffers, calibration/profile/caches, native pool and allocations outside the backing remain additional. Current six output sizes are resampled after full native render; selecting50%/25%/3840 does not reduce this arena. The original 8-row worker regions view already-allocated whole intermediates, so they are not a demonstrated low-memory tile route.

Both actual Boot DTBs declare 8 GiB in their memory regions (low2GiB + high6GiB); the second additionally lists reserved regions. The collector reads the exact `/memory/reg` and reserved-memory bytes directly from each hash-checked Boot DTB. This is firmware configuration, not observed physical RAM or current available capacity. Do not infer that 3 GiB is impossible, but do not promise safe anonymous allocation, native completion or performance from the declaration. A map or overcommit success is not a reserved physical budget.

The concrete remaining no-card source gaps are: capture producer completion for encoded extent/row table and physical allocation; independent source/node/resource lease after the original Host task; checked black/calibration/profile ownership in the RAM branch; a new source interface compatible with combined receipts; and actual safely held RAM budget. The original Host full-IIQ writer route should remain normal and retain RAW if any of these fails. No 4K/thumbnail substitute or silent size downgrade is supported by this review.

EXACT.json contains ten finite original windows, their exact words and hashes, Boot DTB property bytes and checked arithmetic. This is static/resource evidence only. No native decode, color render, JPEG encode, Capture One transfer or memory allocation test was run here.
