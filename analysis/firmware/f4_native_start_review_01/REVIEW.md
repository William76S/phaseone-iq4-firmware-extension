# Original native LV start and queue global guard — finite read-only review

Root reports the device as P1Linux 6.03.30 and confirms the original live view was already updating before the recorder Start action. This review therefore does not propose adding a guessed native Start to fix that observation. It did not access the device or run any original function. No frozen implementation was edited.

The original queue guard is not waiting for LV startup. `0x712000` tests the nonzero pointer at `0xf553a8`. Original loaded file data contains `0x409c10` there. The original recursive mutex at `0xf553c0` has type word `1` at `+0x10` (`0xf553d0`); neither finite data range is targeted by any original ELF RELA. `0x712324/360/39c` use the same active predicate to call pthread lock/trylock/unlock. Queue registration's `0x712790` acquires this exact mutex. Thus the project's nonzero/type-1 gates agree with original initialized data, rather than with a hypothetical asynchronously created LV object. Runtime mutation, an unreadable address, or a busy mutex could still reject; none was observed here. The type check alone does not prove the whole live list is valid.

Original LV construction establishes its access link before Start: `0x5176a8` obtains the manager data, `0x5176ac` loads data+0x118, and `0x5176b4` writes LV+0x108. `0x51769c` initializes owned to zero. `0x517b7c` registers the native client name and `0x517b88` stores client ID at LV+0x100. The access constructor `0x6b56ec` establishes its exact primary vtable, engine+8 link and unowned client -1. This disproves a claim that these particular fields only appear after Start. It does not prove every exact owner gate or engine event field on this device; those still require the real failed-stage values.

`0x5202a0` takes `x0=actual LV`, returns a U32 boolean in w0, and is called synchronously by original UI enter at `0x51d8b0`. If LV+0x104 is already nonzero it calls `0x5208cc` (resume) and returns one. Otherwise it calls access acquire `0x6b5a6c(access, client)` and stores the returned byte to owned. A false acquisition returns zero before configuration. The normal path resets the original engine, requests 640x480 at metadata+0x58, configures the complete sensor ROI through `0x6b639c` with fit flag one, sets color mode three, invokes access Start, adjusts original controls/scale, starts the 1000ms timer, and sets active. This is substantial original UI state mutation, not merely opening the recorder source.

Normal Start returning one is not a first-frame receipt. Access Start `0x6b5da0` updates native properties; the displayed path has no frame-counter wait or completed-frame proof. The already-owned resume path likewise returns one without proving a new frame. Calling this entry from the same verified native UI thread is consistent with its original enter caller, but synchronous call duration is not established by this finite review. Do not busy-wait on the UI thread for asynchronous production. A future adapter that starts an originally stopped client would also need to track that distinct lifecycle; original stop `0x520590` releases the original LV retained frame, stops interfaces, releases the client, clears owned/active and stops its timer. It must not blindly stop an existing original LV session.

No additional P0/P1 ABI mismatch was found in these 19 exact original function windows. The confirmed earlier P1 remains the held menu erasing diagnostics (`f4_initialization_review_01`), now being addressed by the independent new revision. Original owner/list runtime values, actual native constructor/Subscribe outcomes, clock/thread wrapper returns and the first failed initialization stage remain the needed evidence. This report makes no hardware capability, frame-rate, card, or target-acceptance claim.

`collect.py` is an offline collector. It validates the original User length and SHA, uses unwind-delimited function windows, maps writable globals by PT_LOAD, and records any RELA targeting them. Its page-reference inventory is only a locator and is not an ABI proof. Exact bytes and file hashes are in EXACT.json. No host codec tests were rerun.
