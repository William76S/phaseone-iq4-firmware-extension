# 6.03.61独立重建缺项

结论：当前公开仓库是源码研究快照，不是独立完整重建环境。

## 已有

- 61的4K回退、菜单、图库删除身份和配对删除源码及主机测试。
- 原厂User的精确输入标识：6.03.21，SHA256 `9b611efe64067685b770ba3984ae951684c5a401f73f77a03b316be374032cdb`。
- `build_components.py`、`prepare.py`、`assemble.py`等本地增量装配入口。
- 固定Zig 0.15.2 macOS arm64工具链描述，以及libjpeg-turbo 1.5.3适配代码和许可文件。

## 尚缺的闭合构建流程

1. 需要自行取得有合法来源的精确原厂固件/组件；原厂完整源码不在本项目中。
2. 61的组件入口只重编译runtime/menu/gallery；其余对象和两个初始化对象来自已有冻结工程，配对删除对象另行构建。公开树不附这些对象。
3. 装配依赖60及更早的`analysis/.../INPUTS.json`、生成头文件、对象、源码锁和校验收据。递归校验还会读取旧源码锁引用的历史生成物，不能仅复制最后40个对象解决。
4. 需要把这些依赖改造成有顺序、可自动生成的构建图，并消除本机工具链/旧输出目录依赖；尚未完成。
5. 旧版`rebuild_inputs.py`不能直接当61重放入口：它对61命令记录中相对编译器路径的处理不兼容。旧reproduce脚本也绑定更早的链接与封包流程。

完整重建的验收应是：全新目录 + 明确列出的外部原件/工具链 → 编译全部当前源码 → 链接、版本绑定与封包 → 对比交付FWP。当前没有完成这项验收。

本地研究工程曾完成精确输入下的装配与包校验；这不等于他人仅靠GitHub已经可以复现。公开仓库不会把缺少的本地依赖描述成已解决。
