## New observations and actual boundary

The runtime feeds the new boundary collector only after the real original unlock, Entry snapshot and actual Stack05 collection. Fresh versus prior Entry anchors retain their original dispatch/stack epochs and source relation. Replays, changed owners, wrong frames, unsupported stacks and failed/changed bounded reads clear the current facts rather than carrying earlier facts into a new publication.

The new collector independently reads the same real TP/queue/manager/LV/embedded-popup owner chain and ordinary normal stack. It accepts sole LV, validated Home→LV and their original popup forms; paint must have LV at the tail. Home remains the exact frozen table candidate. It records:

- Actual LV vptr, source epochs and stack shape. Original LV primary or this collector's exact complete private table is accepted; an arbitrary or corrupted shadow is rejected. The shadow is tied to the LV already observed at a real original UI boundary. Memory reads are never altered to impersonate the old vptr.
- Actual manager+0x108 provider, its vptr, ABI header/typeinfo when readable, VT+0x18 getter and VT+0x10 presenter targets, bounded first16 bytes/availability and getter's membership in the pinned original executable PT_LOAD. Manager constructor origin `Configurator+0x9c8` is read and compared. Neither target is invoked. Prefix/range membership identifies a finite candidate, not a complete function/class/lifetime proof.
- Resource aliases manager+0x788 and LV+0xf0, wrapper+0x10 provider/vptr, and original embedded popup title/root/depth/selection. This provides actual arguments needed by the existing native UI ports without choosing a button position or displacing an occupied stock menu.
- Correct cached pan+0x118/animation+0x138, local/recursive candidate bounds, actual/normal-fit f32 scales, rotation/countdown/visible/running, Access/engine/buffer aliases, configuration dimensions, locked slot size/ROI/software ID. Slot4 yields no locked metadata. Config/slot/ROI size equalities and four configuration-corner point-model results remain explicitly candidate relations. They do not assert full sensor/source coordinates, a viewport or a new frame.

The collector performs two agreeing boundary snapshots, including provider targets and resource aliases. A paint observation preserves before/after geometry instead of demanding no native state change. Equality is reported separately. Every attempt is bounded (64 boundary and64 paint samples). A dropped/reentrant/over-limit observation does not inhibit or repeat original paint and does not republish a prior paint as a fresh observation.

## Paint context port now implemented

`iq4_f1_display_paint_callback_06` is a retained AArch64 callback with the exact existing `LVPaint` four-argument/24-byte indirect-result prototype. It captures actual TP, own FP, saved caller and incoming LV/Surface/draw/clip before helpers. Its separately compiled body has FP at the saved pair `SP+0x40`, not an assumed SP0. It calls `forward_once`, which forwards the exact arguments to the verified original `0x51da0c`, once. Original return fields and errno are preserved. Original exceptions propagate; an exception clears pending paint and cannot produce a normal-return record. Whole own linked callback/helper disassemblies record the x8 24-byte return and single original BLR.

Bounded self-reads before/after that call verify caller `0x4abe94`, actual Control saved LV+0x48/Surface+0x40/draw+0xb8/clip+0xd0, saved Manager caller `0x4e33bc`, Manager+0x28/Surface+0x148/LV+0x150 and actual provider. Surface reads end at `[0,0x38)`; Draw identity, pitch/height and bounds are recorded, with before/after clip/extent equality separate. No Surface+0x38 pixel pointer or source-slot pointer region is read. Observation failures still forward original paint once. Publication writers are serialized by a private atomic flag; no original mutex/tree is acquired or written for these new facts.

This callback is **not installed**. A plain Observe-only load can obtain the new boundary/provider/resource/geometry facts, but cannot manufacture a paint input. The paint record remains absent until the sole executor has separately bound a reversible RAM table trial to the exact observed LV/callback/module and verified restoration of the original vptr. No helper here performs that write. The existing production overlay/UI configure guards remain unchanged and reject.

## What the first actual OFF observation can settle

One actual Observe-only session can settle the UI owner/stack shape, correct provider dynamic targets/bytes, resource alias arguments, occupied-popup state and normal-view scalar/config/ROI relationships. It cannot settle full-source mapping, inner clipped pixel coverage, lease, clickability, OFF restoration or callback quiescence. Once a separately reviewed original-first paint observation is installed, the same publication can also settle the actual saved-frame/Surface/provider relationships and native geometry changes across that call. Positive paint return/countdown0, stable publication, software ID and source epochs still do not certify completed full image writes or new sensor frames.

The next specific gaps are the complete actual provider getter body and ownership/release contract; actual source↔screen relationship across stock zoom/pan/quarterturn; and a transparent actual inner display-write/normal-return/clipped-coverage receipt. The existing frozen RGB24 route `47583c..475904→47f910`, default row `47e930→9e9598` covers one branch only. Replacing Draw VT+0x18 changes the `47f910` fastpath, so this increment does not do that. Original `51dd40..74` skips image writes on countdown yet returns the incoming draw rectangle; `477038`/`47552c` returns are not actual clipped coverage.

For the user entry, Entry01 already concretely supplies native TLS current, bounded original-lock listener inspection, invalidate repaint and fill ports. The smallest existing positive route is an owned text button→owned Control observer→unique queued OsEvent→owned native selector/private five-item root, preserving toolbar tags1/8 and LV+0x588. Frozen `f1_entry_button_ports_01` supplies constructor/bind/attach/detach prototypes; placement/hit-test/current input capture and private popup owner branch still require actual observations/new source. Reusing UI02's shared LV+0x588 popup after stock menu use is insufficient: original exit `4e1960` leaves its root and UI02 correctly rejects an occupied root. This observation increment records the relevant existing owner/root/resource facts and does not fabricate that entry.

## Verification and freeze

`build_validate.py` verifies frozen dependency bytes, executes only21 owned host fault/forwarding fixtures plus21 decoder checks (normal and ASan/UBSan), then compiles/links/inspects AArch64 without loading. Host/target publication offsets, original call count, actual FP placement and x8 return are checked. Source compatibility and static rootfs symbol providers do not attest runtime loader/native object ABI acceptance. Exception propagation adds `__cxa_rethrow` and `_Unwind_Resume`; their original rootfs ELF providers are recorded separately, without launching either library.

`freeze.py` creates the new source/dependency/artifact hashes once. `validate.py` only rechecks those bytes and the false acceptance fields. Frozen components/reports, including both Baseline03 refusals and strict PE startup false, are not changed. No actual camera/SDK/Windows/network, install, mask or persistent recovery acceptance is supplied by this stage.
