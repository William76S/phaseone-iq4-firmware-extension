# Native card bridge 05

This is local cross-compiled source, not camera validation. `python3 tools/firmware/f3_native_card_bridge_05/build.py` runs only our host fixtures/temporary files and compiles AArch64 ET_REL objects. It never executes those objects, vendor functions, SDK, or a device.

`f3_card_begin_05` resolves real SDWrite/XQDWrite from the original global list and id10/id11 LinuxFS objects, verifies exact original method/vtable bytes, registers one permanent own client pointer, requests each required original power owner and waits with the original 6000 ms method. The registration is retained until original User exit; no unproved unregister or SO unload. The actual request mask at +0x17c is not a card epoch. Desired power state notifications are real side effects of acquiring/releasing these original requests; they do not write PIN/configuration or create/delete files.

The caller must invoke the native waits on an existing original task thread: the original wait uses 0x710b0c→0x713f60, which reads native thread TLS at TP+0x10. This bridge creates no thread and cannot make an arbitrary pthread into an original native thread. The caller's bounded own-memory reader must reject unmapped addresses, not directly dereference guesses. The recovered actual constructor bindings, complete register/wait/release bodies and 9/38-slot vtables are in the static evidence and ORIGINAL_BINDINGS.json.

The real root strings at LinuxFS+0x15 are double-read; only `/run/media/sdcard/` or `/run/media/xqdcard/` is accepted for the matching registry owner. The bridge opens its own independent root directory descriptors using original syscall PLT aliases. It never borrows the native File descriptor. It reads only `/proc/self/fdinfo/<own FD>`, with a bounded 512-byte complete newline/EOF parser requiring exactly one positive mnt_id. Rootfs fstab mounts proc, and the fixed Boot kernel seq_show outputs the file mount ID; runtime missing/unreadable fields reject. The value used by CardGuard is the actual JPEG root mnt_id. RAW and JPEG held descriptors, fresh root opens, parent `/run/media` mount ID, device/inode, root owner/name and native request bit/mode are rechecked for every guard. An unmounted root sharing the parent's mount ID is refused.

This is a mounted-view generation check, not proof of physical hotplug immunity. A detached or altered mounted view, unavailable original owner, unexpected close/release or native exception latches UNKNOWN. Existing owners and FDs remain held, no retry/close/delete/second job is attempted. The exclusive process-wide actor serializes our private filenames; stat→unlink is not inode-conditioned against an independent concurrent writer. All other original producers must remain outside this private generated namespace.

Use `raw_dir` and `jpeg_dir` only while state=2 and `f3_card_valid_05` succeeds. Root's scratch arena and the JPEG/recording sinks can consume the same CardGuard. `close_dirs` then `release_requests` is split so the source lease remains held through source-reader, arena, RAW and directory FD cleanup. Cleanup failure preserves the remaining owners. Callers must not release the card request before those owners are clear.

`fs05.c` is a mechanical FS04 body derivative. Its only functional change accepts limited ASCII case-sensitive basenames and exact `.IIQ` or `.iiq`; no slash, traversal, arbitrary extension normalization or symlink is accepted. Manual source descriptors are independently opened read-only and adopted only after matching FD/path identity. Manual existing IIQ is never eligible for deletion. Link fs05.c instead of frozen fs04.c, since their preserved `_03` symbols are the same ABI; do not link both.

Actual checks: 13 isolated card fault cases, 12 fdinfo parser groups and 9 real host manual-file groups passed under normal and ASan/UBSan; five target objects compiled. Card objects/mount IDs in host tests are explicitly synthetic, while the manual filenames/files are real local temporary files. No camera mount ID, native task acquisition or physical card epoch was observed.
