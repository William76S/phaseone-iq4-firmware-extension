# UI async card acquisition 06

This independent derivative preserves the frozen Card05 data layout and `_05` function ABI. Link the 06 card.c/native_calls.cpp and helpers **instead of** 05 implementation objects. Do not link both: duplicate functions would also create different permanent client-name pointer ownership. Movie01 may include the frozen 05 type header; the ABI is unchanged.

`f3_card_request_06` is called once on the actual original UI task. It verifies original SDWrite/XQDWrite owners and immutable code/vtables, resolves current original TLS thread via the actual 0x710b0c→0x713f60 getter and requires its primary VT=0xb91f48. It registers its own permanent client slot, invokes original non-blocking Request(0x8ca598) once per required card, and checks its real request bit. No native wait or sleep is used. Return 3 means PENDING with requests held and no directory files adopted. No current-mode value is fabricated.

`f3_card_poll_06` on that same actual UI task reads original mode at owner+0x320, verifies requests/identity and returns PENDING until each mode is actually 1. Only then opens original actual roots and binds mnt_id/device/inode as Card05. The caller schedules finite UI observations from its actual control/timer route and can call `f3_card_cancel_pending_06` once on the same original UI task to release a known pending request. This library has no automatic timeout, repeated request or hidden rescheduling. Unknown original Request/owner/identity preserves requests and blocks all future actions.

After READY the plain recording worker uses `f3_card_valid_05`, CardGuard and held raw_dir/jpeg_dir. Those functions do not query native TLS or invoke a native request method. The worker may close the directory FDs after actual source/encoder task fence and file cleanup. Native `release_requests_05` is admitted only back on the same actual original UI-thread object captured at Request; calling it from a plain worker latches HOLD before any original release. The actual UI receipt must not be generated merely from a finish-call attempt.

The same mounted-view limitations, permanent registration lifetime and UNKNOWN ownership rules documented by Card05 apply. The one additional path correction removes a native root's trailing slash in the local copy passed to openat, retaining original exact root bytes in the guard. This makes O_NOFOLLOW cover the actual final root component; it does not normalize arbitrary paths.

Seven isolated normal and seven ASan/UBSan cases verify original wait is never invoked, real modeled pending/ready transition, pending cancellation, wrong UI VT rejection before native calls, Request exception retention, changed native UI identity retention and plain-worker release refusal. A case proves plain-worker validity/FD close performs zero current-native-thread lookups and subsequent UI release succeeds. Five target ET_REL objects compile. UI object/card/mounts are explicit host fixtures; no native target/device calls were executed.
