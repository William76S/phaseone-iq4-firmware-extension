# Executor03 dual-card saved admission

Replace the frozen Executor02 `executor.o` with this single object. Keep the original Executor01 `native_calls.o` and `wait_wrapper.o`, one shared `activity.o`, Coordinator08, and Producer03. All existing `_01` public signatures and the original native IFM wait hook are retained. Three new `_03` functions reserve, cancel an unqueued saved reservation, and invoke that reservation; they require Producer03's real static-slot/group proof. No new original function alias or extra branch patch is introduced here.

The SD and XQD native save callbacks borrow one process-lifetime producer group activity. They reserve the one IFM mailbox before Coordinator08 prepares its one Job. Waiting is limited to 600 seconds. A pre-enqueue refusal or timeout means no Notify or source transfer occurred; the original native save can acknowledge normally and retain its RAW. A normally ended saved render clears only the mailbox, leaving the producer's card, File and group cleanup to their actual owners. Notify failure, queued timeout, changed ownership, unexpected worker result or original Wait exception latches Hold without release or retry.

The actual saved callback is identified by the producer's static receipt, immutable capture sequence, actual card ID 10/11, group lease and matching original pthread self. The original SD/XQD storage VTs remain exact; UI and IFM worker callers are rejected. UI submit/cancel cannot replace a borrowed saved reservation. Selected-mask bits describe actual native selected/notified JPEG destinations, not completion or inferred card presence. Only Producer03 may release the shared group after its exact fanout seal and normally ended selected callbacks.
