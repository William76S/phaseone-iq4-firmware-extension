# Native SD/XQD storage bridge 01 — offline component

This component connects the shared F3 format choice to the original complete-RAW storage route. It is not an independently installable firmware or a camera acceptance result. Input is stock User P1Linux 6.03.21, SHA-256 `9b611efe64067685b770ba3984ae951684c5a401f73f77a03b316be374032cdb`; the parent integration must verify every original patch word and preserve the linked seal.

`iq4_f3_native_mode_set_on_ui_01(card, mode)` accepts card 10 (SD) or 11 (XQD), with F3 RAW=0, RAW+JPEG=1, JPEG=2. It runs on the verified original UI queue, checks the relevant backend capability and shared activity ownership, calls the original StorageMode setter with Optional=2, reads it back, then commits one existing F3 policy update. It does not bypass native card presence, space or checked-write errors. The downstream existing F3 pipeline obtains a complete RAW; JPEG-only deletion is still conditional on its verified JPEG completion and source ownership. No thumbnail is used as the full-size source. Size and quality remain the existing shared policy values.

The visible original SD storage combination menu is replaced by SD output (RAW/JPEG/RAW+JPEG); Capture Output uses the same API/state. The original menu chain eagerly constructs Storage Setup before File Settings, so entering Storage Setup first is unnecessary. The legacy thumbnail/4K worker's two mode reads return disabled only after immutable `iq4_extensions_installation_stage_02()==100`. Before successful initialization they call the exact original getter, including original exception propagation. Runtime Hold cannot reactivate the old worker. Pair this component with `f3_native_size_menu_02`, which applies the same installation gate and replaces only the original JPEG Size menu with 4K/8K/75%/50%/25%/100%.

The original 0x40c310/0x40c340 RAII methods are NullLock constructors/destructors, not mutex operations. A separate original libpthread default mutex now brackets only the two StorageMode setters' load/compare/store regions. The entry/exit hooks are 0x5e9884/0x5e98c0 and 0x5e9900/0x5e990c. All original normal branches, including same-value/no-notify, pass the exit; unlock occurs before original notification. Only the two bound card events acquire this mutex. Precise old combination caller PCs may retain Optional while the new choice is active. Other native Off writes clear that override and inhibit explicit rearming until native nonzero restoration; the Off value is preserved. UI arming occurs inside the same mutex. No spinlock or global native setter replacement is used.

Initializer must call `iq4_f3_native_storage_mutex_initialize_01()` after exact installation checks, before coordinator installation/menu construction; success is exactly 1. The parent uses stage45. Its static 48-byte, 8-aligned default mutex is verified against stock `/lib/libpthread-2.28.so` SHA `9305ff30980749a3f64b3e445764db2bc378d14d1ef8bbe004d0ecc768d00f77`, then real original lock/unlock return values are checked. Failure must leave installation stage below100. Runtime errors prevent F3 policy commit and require investigation; they are not reported as Ready.

Original StorageDTO enums are never expanded or persisted with invented values. Original native storage values before each card's first explicit selection are retained in RAM for diagnostics. Native Off/restore does not automatically rearm the override. Consequently a Black Reference/protection cycle or subsequent original combination notification can require selecting the format again. BR-05 automatic recovery is **not completed or accepted**. This component does not claim original error/BlackRef compatibility beyond the finite tested Off/restore cases. Disabling/recovering the complete candidate requires the parent exact stock firmware recovery procedure and the user's saved XFSystem.set; cold startup discards this component's RAM state. It does not write calibration, security records or card metadata itself.

Completed validation: 25 normal and25 ASan/UBSan host process cases, 9+9 original-call/exception gate cases, 300+300 actual host pthread interleavings; four finite mutex-init cases. Actual original AArch64 setters plus compiled wrappers execute in host Unicorn for108 chains, checking padding tokens, caller x19 preservation and same-value unlock. Original libpthread init(NULL) produces exactly48 zero bytes, and three original uncontended A64 lock/unlock cycles pass with synthetic TLS. These are host tests with explicit UI/notification/native-call fixtures, not device execution. Target objects rebuild byte-identically twice. No camera or Windows access occurred.
