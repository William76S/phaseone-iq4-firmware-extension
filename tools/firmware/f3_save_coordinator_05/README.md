# Checked save coordinator 05

This synchronous actor calls the frozen `f3_native_render` and the actual streaming RGB32 JPEG codec. Its internal job is always RAW+JPEG: checked write, close, whole SHA256 readback, JPEG SOF/SOS/EOI/dimensions and non-replacing publication happen while RAW remains held. Only after the renderer actually returns with generator, both CIBs, workers and renderer-owned job all clear may immutable public JPEG_ONLY delete its own newly-created stage. Manual existing `.IIQ`/`.iiq` is never deleted, even when public mode is JPEG_ONLY. A native cleanup exception after publication preserves RAW and all remaining owners.

The source/card leases stay held through the delete and final source-reader, arena and independent RAW/directory descriptor cleanup. `close_source_reader` must call actual ReaderStage::shutdown and return checked success; SourceBundle::cleanup alone does not close that native reader. The native reader FD remains distinct from the transaction's independent FS.raw_fd. Image_core's actual source binder must verify its own held FD against ReaderStage; this coordinator never substitutes our FD. Root's concrete reserved mmap arena supplies checked close_arena. The independent source lease releases only after every reader/file/arena/directory FD is known clear, and native SD/XQD requests release last.

Use this native synchronous actor only in a verified original native task context. In particular card request release and full-RAW native renderer are not promised safe in an arbitrary plain pthread. A future asynchronous UI/worker adapter must route original request acquisition/release to the original task while the worker uses only held FDs/CardGuard; it must not pretend that this synchronous function already implements that handshake.

UNKNOWN preserves live source, renderer, arena, file/card owners. A second f3_save_run returns the same held result with no operation. Cleanup FAIL also becomes UNKNOWN because no success proves the owner is clear. Rejected state0 never adopted caller leases. If the RAW hash changed while its original owner remained valid and locatable, known failure retains RAW. RAW-only never constructs JPEG/render objects.

Host evidence is ten isolated cases each normal and ASan/UBSan, with the real libjpeg streaming encoder and real local files. Actual frozen renderer/job/stream/FS logic is linked; only vendor objects/native calls, native source and mount IDs are explicit fixtures. Cases cover newly-created JPEG_ONLY, manual preservation, RAW+JPEG, renderer destructor failure after publication, short sink write, changed mounted view before delete, reader close failure, arena close failure, source release failure and RAW-only. The tests verify deletion occurs after image/generator cleanup and before any source/card release. They are not complete RAW decode or camera tests.

`python3 tools/firmware/f3_save_coordinator_05/build.py` reproduces these host checks and compiles one AArch64 ET_REL, without executing target/native/SDK code. Concrete actual source construction, card acquisition and arena reservation remain integration responsibilities of their real binders, not caller booleans inferred from dimensions or thumbnails.
