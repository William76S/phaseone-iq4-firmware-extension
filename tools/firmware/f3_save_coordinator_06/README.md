# Native save coordinator 06

This is an actual callable production integration, not a hardware acceptance.
No SDK/camera/Windows/target is executed by its build. Install on original startup
before File Settings constructs Menu04. Installation immediately verifies Root's
actual current linked-ELF contract, then only self-reads fixed original prefixes,
binds API tables and configures Capture01's saved callback. It does not create a
Reader, card request, arena or native worker/pool on the initialization/UI thread.
Ready reads atomic installed/hold publication and rechecks the immutable contract.

## Actual execution

Manual uses Menu04/Executor01's actual selected IFM/index and activity reservation.
A short original catalog-mutex snapshot supplies true selected name/FS/folder and
constructor dependencies. Task.sequence must remain the executor reservation's
sequence; Job.generation is a separate internal file/source identity. Manual always
keeps the existing IIQ even when capture settings request JPEG-only.

Automatic is currently SD-only. Capture01 checked Store+Close, exclusive original
RAW creation and whole readback produce its receipt. The synchronous saved callback
copies dependencies while the node is still live, then invokes Executor01 once.
SD waits for the same real IFM BackgroundThread's known-end ACK; the worker never
dereferences the retired capture node. SD card/file/activity owners stay held.
XQD automatic RAW remains unchanged rather than assuming an unchecked close.

The actual IFM native CThread (not plain pthread) opens its own same-FS Reader.
Its held native FD is independently inspected and compared to the held source inode.
Source01 checks complete encoded sections/rows/metadata. Source dependencies and
Card06's mounted view remain held and freshly rechecked. Fully reserved exclusive
file-backed arenas hold encoded padding and original generator backing. The arena
size is a finite actual attempt, not a proved native working-set upper bound.

Render02 requires actual decode/core receipts, FullR0 RGB32 and Root's current
linked-ELF static unwind proof. Export04 replaces only the two03 objects and preserves
its C ABI. It area-resizes all six options and streams real JPEG to checked SHA/SOF/
EOI readback/non-replacing publication. Neither this operation nor dimensions infer
successful native pixels. If encoder cleanup is UNKNOWN, its C function fully returns
before the C++ sink throws Retain06 into Render02's quarantine catch; no C callback
throws and no subsequent renderer/source/arena/file/card cleanup occurs. The Job and
all copied encoder/plane/context owners are process-lifetime nonmoving storage.

On normal render return, every native live/join/receipt/source-borrow bit must be
clear. The actual pool release and SourceBundle cleanup precede any RAW deletion;
source/card and original Reader FD continue held. For SD JPEG-only only, publication
and the true exclusively-created captured RAW are rechecked. Public name is atomically
moved non-replacing to a task-private quarantine, then opened and whole-hashed again.
Only the same original inode/content may be unlinked under the serialized private
namespace. A raced foreign file is never deleted: restoration is non-replacing and
failure retains every owner. This is not inode-conditional unlink on a public name.
Unknown epoch/owner/read/sync/close refuses all later operations. Unsupported rename
or a known preserved source yields JPEG-with-RAW rather than pretending JPEG-only.

Then checked native Reader shutdown, arena end-loan/release, source FD and own parent
close occur. Manual Card06 request release is last. Manual activity is released by
Executor01 after normal completion; saved capture/activity owners are released only
by the original SD callback after ACK. A known no-enqueue rejection preserves stock
RAW and permits original cleanup. UNKNOWN keeps reservation/card/source/pool/activity.

## Build and evidence

`python3 tools/firmware/f3_save_coordinator_06/build.py`

Two AArch64 objects are compile-only.16 actual Mac POSIX file faults normal/sanitized
cover nonreplacement, name races/foreign restoration, zero publication, changed
identity, short read/EOF, epoch losses, sync/close failures and no operation after
Hold. Mac renameatx_np(RENAME_EXCL) is a host test adapter, not evidence for target
renameat2 support. Another16 tests directly include the actual cleanup/sink bodies,
with explicit native callback fixtures: ordering, each cleanup failure, no retry,
and encoder-completed Unknown retaining all owners. No old implementation-mirror
model substitutes for these bodies. Actual native CThread, card, full sensor decoder,
C++ target unwinding, speed, capacity and output behavior await device acceptance.

overlay; Executor01/Menu04/activity01; Card06 card.c/fs05.c (never also Card05 or
FS04 bodies); Source01; Render02 including its actual codec/decode/completion hooks;
Root Arena01; Export04 two-object overlay on03 + its original27-member source closure.

actual reviewer callback/SHA with kind exact-linked-ELF-static and target-unwind
accepted=0. This package does not synthesize a positive reviewer. PersistentPool remains
process-lifetime and is initialized only on that one original background CThread.
