# Coordinator08 serial SD/XQD saved jobs

Replace only the frozen Coordinator07 `coordinator.o`. Keep its original Coordinator06 `public_raw.o` and use Executor03 and Producer03. All menu-facing `_06` function names and structures remain unchanged. Manual export remains RAW+JPEG and never obtains a deletion ticket for an existing IIQ. Size, RGB32 borrowing, render receipts, codec, source/reader/native-pool cleanup and checked publication are unchanged from the frozen implementation.

Saved callbacks now reserve the sole executor mailbox before preparing the sole process-lifetime Job. A second card waits for that reservation instead of racing or overwriting another card's Job. Producer03 supplies the actual immutable early constructor-dependency snapshot, rechecked while the original saved callback and card owners are held; no late RawManager current-node getter is used. Preparation refusal cancels only an unqueued mailbox. Before-admission BUSY/REJECTED returns a normal original RAW acknowledgement without preparing or mutating the other Job. Any unknown admission, preparation, notification, run or cancellation retains the actual receipt/group and executor owners.

The native SD and XQD stores consume RAW memory payload/metadata and write independent card files; they do not read a peer card's IIQ. Producer03 creates each own file exclusively. JPEG-only removal therefore uses that card's exact own inode, held FD, whole-file hash and actual source/render cleanup while its card/source owners remain held. The implementation does not claim that a peer write has finished and does not delete a peer or pre-existing IIQ. Producer03's original-fanout seal and finished selected-mask close the shared activity lifetime independently of the per-card file deletion.

`saved_route.hpp` is the actual production routing helper, also executed by fault fixtures. `analysis/firmware/f3_save_coordinator_build_08_attempt04/COMMANDS.json` records 18 routing groups, 5 actual saved-prepare groups, 11 inherited known-no-enqueue/retention groups and 16 actual cleanup/sink groups in normal and ASan/UBSan builds, all exit zero with empty stderr. Native/card/file callbacks are fixtures. Coverage includes pre-enqueue refusal preserving an unrelated Job, cancellation failure, an invalid completion result, null prepared ticket, queued Unknown and C encoder Unknown returning fully before the C++ retention exception. Two AArch64 ET_REL compilations are byte-identical. These are host and static build results, not camera acceptance.
