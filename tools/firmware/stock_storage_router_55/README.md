# Storage router 55

This replaces the 54 JPEG runtime and 53 SD-policy bridge. XQD Storage chooses IIQ, JPEG, or IIQ+JPEG. Original SD Storage remains the native property; SD Primary and SD-only use the same format. Overflow follows the actual completed RAW source. Archive/JPEG-only destinations publish independently checked JPEGs to both cards. The original full IIQ is kept as temporary source; only the separate positively identified fresh-capture receipt may retire it after every requested JPEG has synced and all native source/output/backup consumers have ended. Old photos, BlackRef and diagnostic frames are never retirement candidates.

JPEG-only requires the actual independent JPEG catalog/LCD provider. A cold JPEG-only configuration first binds real card clients and fresh RAW receipt, then binds that provider and enables JPEG New. A missing capability leaves RAW available and reports a finite refusal or ownership HOLD; it cannot produce a fake Selected state. Native JPEG Mode is now owned by capture format. Format and JPEG Size changes reject capture, active receipts, pending256 or card leases rather than clearing old jobs. Independent atomic settings are stored only in `/mnt/qspi/iq4-storage55.cfg` with checked backup/recovery files.

Archive's native Backup All setting can be changed through its original event setter to New only while capture is idle, pending128 is zero and both exact BackupStorage clients are quiescent. The old value is retained for restoration if format save fails. Active backup refuses the request with the short Archive status. JPEG-only Archive suppresses only this owned new capture's native RAW-backup enqueue; the receipt rechecks the same catalog slot and backup quiescence before deletion. IIQ and IIQ+JPEG retain original RAW/backup behavior.

## Half fixes

Native request+28/worker SP428 carries `node+dc`, a globally assigned processing identity. It is different from the catalog slot index in `node+d8`. The old54 lease compared those independent domains, rejecting valid Half requests. The new transaction snapshots the UID, checks the original processing scope against that UID and still queries the catalog using its slot index. `native_half_failure_audit_55/A64_UID_WORKER.json` executes the original assignment/getter/copy fragments with UID1001 versus catalog7 and binds the shared native ICE queue. The unchanged producer remains guarded by its original three hooks.

Original ImageForJPEG has its own 10-second wait at48c98c. Only a matching owned Half request—same catalog, slot, held node, UID, Main worker's ICE queue and observer stack—uses 60 seconds; other requests retain 10 seconds. The owning JPEG wait uses90 seconds. A finite gate prevents a still-running inner request from surviving reuse of the job buffer; an early outer return retains HOLD. These values are timeouts, not hardware speed claims.

Original JPEG failure cleanup returns5 after releasing clients but does not clear pending256. This can leave the shutdown Saving counter permanently nonzero. New finite failure cleanup calls original8e25b0 only after Half and all our native tokens have ended. A guard inside its native catalog mutex at497630 rechecks the exact catalog/slot/node before the original pending operation. It clears pending256 only; RAW flags and JPEG done16 are unchanged. Unknown ownership stays HOLD. One actual first-error stage is available through `status.h`; no diagnostic GUI tree is added.
